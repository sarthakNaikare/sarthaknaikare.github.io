// LESSONS, PAID FOR IN BUGS

THINGS PRODUCTION TAUGHT ME

LESSON 01
Zero is a number, not nothing.
My market data recorder stored zero traded volume as null, because Python quietly treats 0 as False. Rows of "missing" data that were never missing.
THE MORALDon't erase what's real just because it looks small. Check for None, not for falsy. Works for people too.
LESSON 02
The scariest bugs don't crash. They smile.
An index feed passed every check while two of its most important symbols quietly vanished. Unset protobuf fields aren't None, they're polite empty objects that look truthy.
THE MORALA quiet system isn't a healthy one. Verify what's actually there, not what should be there.
LESSON 03
Don't grade your own homework.
I reviewed a kill switch whose proof of success was asking the same code that did the killing whether it worked. Shockingly, it always said yes.
THE MORALProof needs an independent witness. In code, in reviews, and in life.
LESSON 04
A guard that cries wolf gets ignored.
A tighter risk limit looked safer on paper. Then the numbers showed it would fire during perfectly normal trading, so it was withdrawn before it ever went live.
THE MORALStrict isn't the same as safe. A good alarm rings rarely and means it every single time.
LESSON 05
A safety net that never fired proves nothing.
A limit that has never triggered is either perfect or broken, and you only find out which on the worst possible day. So now I drill my safety nets before anyone falls.
THE MORALTrust is earned by tests, not by silence.
LESSON 06
Measure twice, push once.
I once bundled stop, commit and push into a single command because it felt efficient. It was efficient. Efficiently terrifying. Now every irreversible step gets its own yes.
THE MORALSpeed is great, undo buttons are better. When there's no undo, slow down.
LESSON 07
The query wasn't slow. It was lost.
A TimescaleDB query took 8 seconds. EXPLAIN ANALYZE showed it scanning every chunk because the planner couldn't exclude any. One fix later: 200ms, 96% faster.
THE MORALBefore throwing more power at a problem, find out what's being wasted.
LESSON 08
Rejection is data, not a verdict.
Three rounds, one rejection, one very long evening. My dad told me not to give up, so I read the "no" like a failing test: check the logs, fix what broke, run it again.
THE MORALGet up before the count ends. The wrestling mat taught me that long before code did.
